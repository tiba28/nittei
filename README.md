# nittei

心理的負担を解消する匿名日程調整アプリ

https://nittei-green.vercel.app/

## 1. 背景・課題

従来の日程調整ツールでは回答（○や×）が可視化されるため、以下の心理的摩擦が発生している。

- 「自分だけ暇だと思われたくない」という見栄。
- 「特定の人が来るなら行きたい/行きたくない」という本音。
- ホストが回答状況を見て、気を遣って日程を決められない。

## 2. 解決策

- **完全非公開回答：** 他の参加者の回答を一切見せず、ホストのみが管理。
- **裏条件：** 「Aさんが来るなら行く/行かない」という条件を、誰にも知られずに設定可能。
- **ホストの負担軽減：** 参加者の本音を集約しつつ、メンバー選択時の心理的障壁を下げる。
- **回答締切：** 締切日を設定でき、ゲスト側にカウントダウンタイマーが表示される。
- **Googleカレンダー連携：** ホストが日程を確定後、参加者のメールアドレスを指定してGoogleカレンダーにイベントを登録できる。
- **メッセージ生成：** 日程確定・見送りなど状況に応じた参加者への連絡文をワンクリックで生成し、コピーできる。

## 3. 技術スタック

- **Next.js (App Router):** 裏条件など公開されてはいけない情報をサーバーサイドで処理し、クライアントに隠蔽する設計。
- **TypeScript:** 型安全により、複雑な条件分岐ロジックの保守性を確保。
- **TailwindCSS:** CSSファイルを別途管理せず、クラス名でスタイルを直接指定できる点を採用。
- **Supabase (RLS):** クライアントから直接DBアクセスする構成でも、行レベルセキュリティで他参加者の回答や裏条件を保護できる点を評価。

## 4. 技術的挑戦と課題

開発過程でAIツールを活用しつつも、大規模なコード生成時に意図しない削除やデグレードが発生するリスクを経験。この経験を通じ、AIの出力を鵜呑みにせず的確に指示を出し自分で確認すること、および変更履歴を細かく管理することの重要性を痛感した。

**既知のセキュリティ課題：** 現状、一部のロジックがフロントエンド側に残っており、開発者ツールでのデータ閲覧可能性を認識している。

**解決策（Next Step）：** すべての条件判定ロジックをバックエンドのRoute Handlersへ完全に移行し、SupabaseのRLSを厳格化することで解決予定。

**AI集合駅提案機能（保留中）：** 参加者の最寄り駅をもとに集合駅を提案する機能をGoogle Gemini APIを用いてバックエンドAPIとして実装済み。無料枠では応答速度・提案精度が実用レベルに達しないと判断し、有料機能としての提供を前提にUIへの組み込みは保留中。
